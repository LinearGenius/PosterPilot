# 中文双页面与响应式改造

## 1. 本轮目标

把项目从“介绍与操作混排的单页”调整为职责清晰的双页面，同时统一用户可见文案并补齐多端布局：

- `/`：项目介绍页，负责解释产品价值、能力与执行流程。
- `/studio`：实际工作台，负责提交需求、查看画布与观察执行轨迹。
- 除产品品牌 `PosterPilot` 外，用户可见的功能文案统一为中文；类型名、事件码等仅保留在代码内部。
- 桌面端工作台在一个视口中完整显示三块核心功能。
- 平板和手机端按可读性重新编排，不强行压缩成不可操作的“一屏”。

## 2. 页面拆分

### 2.1 介绍页

介绍页保留品牌导航、主视觉、核心能力、实现流程和进入工作台的行动入口。页面只解释“它是什么、为什么这样实现”，不再承载表单与运行结果。

### 2.2 工作台

工作台采用三栏结构：

1. 左栏：设计需求与运行入口。
2. 中栏：结构化图层生成的方案画布。
3. 右栏：追问、状态和事件执行轨迹。

页面使用浏览器历史记录完成 `/` 与 `/studio` 的轻量路由切换，并监听前进、后退事件。当前阶段不引入额外路由依赖，避免为两个静态入口增加不必要复杂度。

## 3. 一屏工作台策略

桌面宽度大于 `980px` 时：

- 页面高度固定为 `100dvh`，最外层禁止滚动。
- 顶栏使用固定紧凑高度。
- 工作区高度由剩余视口高度计算得出。
- 三栏内部使用紧凑间距；画布按可用高度自适应缩放。
- 执行轨迹只在自己的栏内滚动，避免整个页面上下跳动。
- 高度低于 `720px` 时进一步收紧表单、标题和间距。

这里的“一屏完整”指三项核心功能入口和当前结果同时可见；当轨迹数量继续增加时，轨迹栏内部滚动。

## 4. 响应式策略

| 范围 | 布局 | 设计取舍 |
| --- | --- | --- |
| 大于 `980px` | 三栏单屏工作台 | 保持输入、画布、轨迹同时可见 |
| `721px–980px` | 输入与画布双栏，轨迹独占下一行 | 避免画布过窄，允许页面滚动 |
| 小于等于 `720px` | 单栏纵向排列 | 保证触控尺寸、文字可读性和表单可用性 |

介绍页在平板端将主视觉与文案改为单列，在手机端隐藏胶囊导航、收紧字号和间距，并让行动按钮占满可用宽度。

## 5. 中文化边界

已修改：

- 导航、按钮、提示、状态、能力说明和流程说明。
- 智能体返回给界面的事件标题与事件详情。
- 页面标题和页面描述。

品牌识别保持英文：徽标使用 `P`，品牌名使用 `PosterPilot`，副标题使用 `DESIGN AGENT`。这部分是产品专有名称，不参与中文化。

继续保留在代码内部：

- TypeScript 类型名，例如 `DesignPlan`、`AgentRunResult`。
- 接口字段和事件码，例如 `waiting_for_user`、`run.completed`。
- 技能机器标识 `commerce-poster`。

这些标识不会直接呈现给用户，保留它们可以维持接口稳定和工程可读性。
