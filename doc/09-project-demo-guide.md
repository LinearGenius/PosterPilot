# 09 · 项目演示与技术问答指南

## 1. 30 秒项目介绍

> PosterPilot 是我独立实现的电商海报 Agent。它不是简单聊天 UI，而是把模糊营销需求转换成受约束工作流：先判断信息是否完整，必要时结构化追问，再生成可校验的 DesignPlan，交给确定性画布渲染，并通过事件轨迹展示每个执行步骤。当前完成了第一条本地纵向链路，下一阶段会接真实 LLM Planner、SSE、图片 Worker 和 Fabric.js 可编辑图层。

## 2. 5 分钟演示顺序

1. 打开页面，说明三栏分别是输入、结果和可观察执行轨迹。
2. 清空产品名称和卖点后运行，展示 Agent 不会盲目执行，而是进入 `waiting_for_user`。
3. 补齐输入后运行，展示 Skill、Planner、画布更新和完成事件。
4. 切换视觉风格/比例，再次运行，说明 DesignPlan 是跨端协议。
5. 打开 `packages/agent/src/index.ts`，讲追问规则和 Planner 替身。
6. 打开 `packages/shared/src/index.ts`，讲结构化输出与画布解耦。
7. 打开状态机、架构和验收文档，说明未来替换点和真实完成边界。

## 3. 常见技术问题

### 为什么这算 Agent，不只是表单生成器？

当前是 Agent 的最小可执行骨架：它有目标、状态、条件分支、Skill 约束、结构化规划和事件记录。现阶段没有假装“自主多智能体”，智能部分是可替换 Planner；项目重点是先把执行边界和恢复机制做正确。

### 为什么不第一天就接大模型？

如果协议、状态和 UI 还没稳定，接模型后很难判断错误来自 Prompt、Provider、网络还是业务逻辑。确定性 Planner 使主链路可测试，真实模型以后只替换一个边界，并保留本地回归替身。

### 空字段为什么返回 200，而非法枚举返回 400？

空字段是用户意图尚不完整，属于预期的 Agent 追问状态；错误类型和未知枚举违反 API 合同，属于客户端请求错误。两类情况的恢复方式不同。

### 为什么不让图片模型直接生成整张海报？

图片模型对精确中文、品牌字体和后续编辑不稳定。项目让模型生成背景或产品氛围图，文字和 CTA 由 Canvas 确定性渲染，才能保持可编辑、可访问和可导出。

### SSE 和 WebSocket 怎么选？

当前主要是服务端向客户端推送 Agent 事件，SSE 足够简单并天然支持 Event ID。画布多人协作或双向高频同步出现后，才有充分理由引入 WebSocket。

### 图片生成失败怎么办？

DesignPlan 和已成功工具结果不丢失，只把对应 ToolCall 标记失败。用户可以重试该工具、切 Provider 或保留占位素材，不需要重新消耗 Planner 和其他已完成步骤。

### 如何防止模型越权操作画布？

模型只能输出白名单操作和结构化参数；服务端验证 operation、目标图层、属性和数值范围，再执行。不会 `eval` 模型代码，也不会把任意工具暴露给 Skill。
