# 14 · 两周求职 MVP 压缩计划

日期：2026-10-11

## 1. 可行性结论

两周、每天 8 小时，名义投入为 `14 × 8 = 112 小时`。

结论分两种口径：

- **可以完成：** 一条真实模型驱动、可编辑、可保存、可导出、可部署演示的求职 MVP。
- **不能等价完成：** 原计划 200–300 小时覆盖的生产化版本，包括完整 PostgreSQL/Redis/BullMQ、对象存储、多 Provider、正式登录权限、高并发、完整成本监控和全面 Eval。

集成、调试、模型波动和部署问题不会因为每天工作时间翻倍而线性缩短。两周方案必须主动减少基础设施和产品范围，而不是降低测试与文档标准。

## 2. 两周版完成定义

两周结束时必须能连续演示：

```text
输入 brief
  → Agent 判断并追问
  → 真实 LLM 生成合法 DesignPlan
  → 必要时单次结构修复重试
  → 生成或选择一张视觉素材
  → Canvas 渲染可编辑图层
  → 修改文字或移动图层
  → 保存版本并撤销
  → 导出 PNG
  → 刷新后恢复项目与事件
```

同时交付：

- GitHub 可阅读仓库和分阶段提交。
- 在线或可重复本地演示地址。
- 20 个固定 brief 的模型成功率、延迟、Token 和成本记录。
- 一段 3–5 分钟演示视频脚本。
- 更新后的 README、架构图、验收记录和面试问答。

## 3. 为两周主动收缩的范围

| 原计划能力 | 两周方案 | 延后内容 |
| --- | --- | --- |
| 数据库 | SQLite + Repository 抽象 | PostgreSQL 生产迁移 |
| 事件流 | 单进程 SSE + 断线续传 | 多实例事件总线 |
| 任务队列 | 进程内任务状态 + Provider 超时/重试 | Redis/BullMQ 持久队列 |
| 模型 | 1 个 LLM Provider | 多模型路由和自动降级 |
| 图片 | 1 个 Image Provider + mock | 多 Provider、复杂抠图和批量生成 |
| 画布 | 文字、图片、背景、CTA 四类图层 | 复杂路径、滤镜和多人协作 |
| 修改操作 | 更新文字、移动、替换素材、撤销 | 任意自然语言设计操作 |
| 身份 | 单用户演示或邀请口令 | OAuth、团队和权限矩阵 |
| 部署 | 单环境演示 | 灰度、多区域、正式 SLA |

这些取舍必须在面试中主动说明：两周版验证产品闭环和工程边界，目标架构保留在文档中，但没有假装已经生产化。

## 4. 每日时间模板

每天 8 小时按以下方式控制：

| 模块 | 时长 | 目的 |
| --- | ---: | --- |
| 实现主任务 | 4.5 小时 | 当天最小纵向增量 |
| 异常路径与测试 | 1.5 小时 | 不把错误留到最后 |
| 文档与面试复述 | 1 小时 | 保证真正理解而不是只有代码 |
| 回归、提交与次日拆分 | 1 小时 | 保持 Git 和验收证据连续 |

若主任务超时，不挪用测试和文档时间；应缩小当天功能边界。

## 5. 14 天执行表

| 天数 | 核心任务 | 当天必须验收 |
| --- | --- | --- |
| Day 1 | 建立 Git 基线；版本化 Prompt；实现可配置 LLM Provider | Key 仅在 API；确定性与真实 Provider 可切换 |
| Day 2 | Zod 错误摘要、单次修复重试、真实 telemetry | 20 个 brief 跑出成功率、P50/P95、Token 与成本 |

| Day 4 | SSE 事件接口、sequence、心跳和重连 | 断线重连不丢事件、不重复事件 |
| Day 5 | Web reducer、运行中状态、刷新恢复 | 刷新后恢复最近 Run 和轨迹 |
| Day 6 | `ImageProvider`、mock、超时、幂等与失败状态 | mock 走通排队、进度、失败和只重试工具 |
| Day 7 | 接一个真实图片 Provider，记录成本并缓存结果 | 成功/超时/额度不足三条路径可复现 |
| Day 8 | Fabric.js 画布、DesignLayer 转换、字体加载 | 现有 6 图层方案在 Canvas 中正确渲染 |
| Day 9 | 图层选择、移动、缩放、文字属性编辑 | 修改后序列化文档可重新加载 |

| Day 11 | 版本快照、撤销与 PNG 导出 | 修改后撤销；三种比例均可导出 PNG |

| Day 14 | 全流程回归、演示视频、面试问答和缓冲 | 5 分钟完整演示；所有声明均有代码或测试证据 |

## 6. 每日停止条件

当天只有同时满足以下条件才算完成：

- 主流程能实际运行。
- 至少一个异常路径通过测试。
- TypeScript 检查通过。
- 相关文档已写入 `doc/`。
- 已形成一个语义明确的 Git 提交。
- 能用 1 分钟口头解释当天的设计取舍。

## 7. 两周版风险排序

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 模型结构化输出不稳定 | 阻塞 Planner | 保留确定性 fallback，限制一次修复重试 |
| 图片 Provider 费用或访问失败 | 阻塞视觉素材 | Day 6 先完成 mock，真实 Provider 失败不阻断画布 |
| Fabric.js 与响应式布局冲突 | 阻塞编辑 | 先支持四种有限图层，不做复杂滤镜 |
| 部署平台不支持持久文件 | SQLite 无法持久化 | 演示环境选择支持持久卷的平台，或把数据库迁移列为替代任务 |
| 连续 14 天高强度导致返工 | 质量下降 | 固定保留测试、文档和每日缓冲，不用熬夜补功能 |

## 8. 第 14 天验收清单

- [ ] 真实 LLM Planner 通过 20 个固定用例并有报告。
- [ ] 信息不足时暂停并结构化追问。
- [ ] Planner 输出非法时只修复重试一次。
- [ ] 页面实时显示事件，刷新后可以恢复。
- [ ] 至少一个视觉素材来自真实 Provider 或已明确使用 mock 降级。
- [ ] 用户可选择、移动和编辑图层。
- [ ] 有版本快照、撤销和 PNG 导出。
- [ ] Key 不进入 Web bundle，日志不打印敏感信息。
- [ ] README、部署、演示脚本和面试材料更新。
- [ ] Git 历史能看出每天的独立增量。

## 9. 不能写进简历的内容

如果两周内没有真实完成和验证，不得写成：

- 生产级高并发 Agent 平台。
- 多智能体协作系统。
- 自研图片生成模型。
- 完整企业级权限和安全体系。
- 已验证的真实用户增长或商业指标。

可以如实写：独立实现受约束海报 Agent 的端到端 MVP，并说明真实使用的 Provider、状态恢复、可编辑画布、版本机制、测试数量和部署证据。
