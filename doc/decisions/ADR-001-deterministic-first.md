# ADR-001：先实现确定性 Planner

- 状态：已接受
- 日期：2026-10-10

## 背景

项目最终需要 LLM 把 brief 转成 DesignPlan，但一开始同时接模型、图片服务、画布和数据库，会让任何错误都难以定位，也会在协议未稳定时产生费用。

## 决策

Phase 1 使用纯函数 `executePosterAgent` 和确定性 `createPlan`：相同输入产生同类结构化结果。它不是最终智能能力，而是 Planner 接口的可执行替身。

## 结果

优点：

- 零 API 成本。
- 单元测试稳定。
- 可先验证状态、事件、API 和 UI 边界。
- 接入真实模型后仍保留为本地开发与回归测试替身。

代价：

- 不能理解开放式自然语言。
- 方案变化有限。
- 当前演示必须明确标注 deterministic，不能把它宣传成模型生成。

## 替换条件

满足以下条件后接入真实 Planner：

1. DesignPlan Schema 稳定。
2. 至少 20 个 brief fixture 已建立。
3. 非法输出的重试与降级流程已设计。
4. Provider Key 确定只保存在服务端。
